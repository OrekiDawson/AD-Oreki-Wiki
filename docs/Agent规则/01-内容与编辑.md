# Wiki 内容与编辑细则

本文件是根 AGENTS.md §2 的强制细则；公开编辑方针、编写指引、文章样板与本规范共同适用。当前执行范围、优先级、分工及临时发布周期由当前授权与任务书确定，不在此冻结历史任务状态。

## 1. 内容组织与作者化

### 1.1 原创内容
- 所有适用公开原创页面，包括首页、专题、玩家百科、教程、攻略及开发者文章，均须逐页判定作者化质量。可按成熟风格保留、深度润色、重组重写、重新研究撰写或边界调整后重写。
- 作者化不是给文章添加感想、趣闻或套用统一模板。允许科普、叙事、数学探索、专题随笔和技术深文等体裁；事实、知识深度、自然中文、趣味及真实阅读价值缺一不可。不得仅改标题/导语、删减有效知识或增加装饰来冒充实质整改。
- 玩家与开发者双专区按实际读者任务设计。一项事实只维护一个权威解释；跨页使用内链，避免重复及过时副本。不能以填充数量、自动生成摘要或审计报告代替知识。
- 页面改造、作者化、视觉组件化、结构调整各自独立验收。涉及同一主题的文章可共享资料研究，按独立文件 Owner 并行实施，不重复编辑同一正文或台账。

### 1.2 玩家文章
- 机制百科说明资源、解锁条件、实际结算、保留项及前后因果；教程按真实界面提供前提、逐步动作、完成判据、常见误区及下一步；攻略解释适用阶段、版本、路线取舍和风险；FAQ 给出可操作的判断与恢复步骤，危险操作提醒备份。
- 原版 Android、原版 Web、MOD Android、MOD Web 的行为、版本和测试证据分别核实。不得把一个平台的实测、历史版本、测试档或目标值冒充另一平台当前事实。
- 真实墙钟约 180 分钟与五阶段体验节奏是设计目标，不是所有玩家的承诺或到时强制解锁机制。不得虚构资源、成就、存档、结算或通关。
- 游戏数值优先使用实际 UI 的科学记数法、单位和精度；纯科学记数法用正文，真正数学推导保留适当数学表达。不得为了格式改变机制含义。
- 名称优先官方游戏术语，避免机械增加「系统」「机制」「阶段」「专题」。正式原版译文使用原版命名空间，重复名称按规范路径区分。公开称呼为 MOD / 本 MOD，技术标识和忠实引用例外。

### 1.3 开发者文章
- 按入门、操作、参考、原理/排障组织，而非按历史任务轮次。架构、接口、ABI、存档、构建、交付等文章以真实源码、实际构建链及原始资料为依据。
- 重写先重新构思读者任务、知识结构和事实依据。旧稿可作事实线索，不能仅换词、调序、补链接或拼接旧段落冒充重写。已合格正文不得重复施工。
- 解释模块、真实调用链与数据流、设计取舍、命令前提、源码符号、可执行步骤、预期结果和失败定位；未执行必须如实标注，不能把资料核对写成运行 PASS。
- Android/Web 技术变更仅在证据支持后同步到 Wiki。目标方案、尚未发布的实现与已验证线上状态严格区分；不冒领业务 Owner。

## 2. 事实、译文、来源与许可

### 2.1 事实核查
- 核对对应源码、原版固定修订、Android/Web 版本、真实界面与运行证据；来源优先原始资料。区分事实、推断、历史、现状和目标。
- 公共正文保留读者需要的来源、版本边界与许可，不堆积核验状态、逐条审计备注或重复参考文献；详细验证、源码行号及日志进入内部记录。
- 公开页面禁止指向 GitHub 具体文件的 blob/raw/raw.githubusercontent.com 外链。源码证据可记仓库、Commit、路径与符号；仓库首页、Release、PR、Issue、Commit 链接按需保留。不得借此删除必需署名与来源。CI 检查源文件和构建 HTML。
- 中西文混排中汉字与 ASCII 字母或数字之间留半角空格；代码、公式、路径、URL、真实标识和忠实引文不机械改写。

### 2.2 原版译文
- 逐段核对英文原版的意思、术语、条件、数值、公式及限定语，不在译文正文混入 MOD 行为、作者发挥或未经证实的新知识。
- 保留原版固定修订、来源、署名、许可及原始贡献者信息；原则上保留上游条目边界。原版译文不按原创作者化标准强行改写。
- 翻译完成、结构核对、语义审校、游戏实测分别记录，不能互相替代。未证实项明确留待验证，不伪造 PASS。
- 本站原创内容适用 CC BY-SA 4.0；第三方文字、图片、字体、商标与程序资源遵循各自许可。素材细则见导航与视觉规范。

## 3. 结构治理与逐页验收

### 3.1 合并、拆分、新增与归档
- 依据知识独立性、读者任务、重复程度和可核实事实决定文章边界；有依据的合并、拆分、新建、替代归档与删除均可实施，不强行改变合格条目、不丢失独有知识。
- 结构整改必须有实际正文和页面关系变化，不能以建议清单、改名、改导航或普通润色冒充完成。
- 每批记录源页、目标页、拆分关系、新条目知识缺口、归档去向、旧新 URL、引用更新、Diff、合并和发布证据。必要兼容入口不得损坏。

### 3.2 台账与独立状态
- 维护全站、玩家、开发者既有逐页台账；以当前实际内容树为准，每个正式页面独立登记路径、URL、类型、处理方式、Owner、正文状态、PR/Commit、复审、合并、部署和线上验收。
- 作者化表达单列，取值为待评估、不合格、整改中、待复审、合格或不适用；仅在完成相应正文复审且确认质量后标合格。原版忠实译文等不适用项注明原因。已合并、已上线、CI PASS 或 Kody PASS 均不得自动推导作者化合格。
- 数值格式与视觉组件化独立记录，不能从作者化或合并状态推导。历史/兼容入口、重定向、归档及草稿单列，不计入正式页面完成率。
- 每批真实改变后更新台账；禁止把台账更新冒充正文交付。全站完成条件由当前 Issue 规定，逐页核对真实证据后结束，不无期限扩张。

## 4. 正文审校

- 作者首先核实事实、来源、中文表达、知识深度、阅读趣味、读者用途、步骤、版权和链接；记录仍未核实的具体事项。
- 保留现行批次复审、Lead 对重点/高风险/争议页面完整审阅及普通合格页面抽查、Lead 自撰独立复审等要求；最新用户授权若明确要求更严格的完整 Lead 复审，则执行较新要求。不能自行取消既有复审职责。具体冲突以当前用户授权、Workspace 和现行任务书核实，不将历史规则当作永久更高优先级。
- 任何应完成而未完成的编辑复审、真实内容错误、版权或可操作性缺陷均标 EDITORIAL_BLOCKED。Kody、CI、Pages 阻断另记，不能代替正文复审。
- 审阅结果绑定候选 HEAD、页面范围、审阅者及实际结论；实质改动后只复审受影响部分与必要上下文，避免重复审核无变化的合格正文。
