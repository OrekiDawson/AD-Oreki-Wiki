# Wiki 审查与交付细则

本文件是根 AGENTS.md §4 的强制细则。Workspace 管理统一授权、六仓 PR 上限、付费并发、预算、环境及资源；本仓仅补充 Wiki 的实际门禁。平台实际保护与用户最新授权优先，不通过规则整理削弱门禁。

## 1. PR 与审查

### 1.1 原子化及优先级
- 一次 PR 只处理独立目标；约 400 行有效变更为软建议，超过约 800 行评估是否拆分，必要原子变更可说明理由。禁止巨型混合 PR、空提交、长期挂 Draft 或重复创建同一任务。
- 先收口已开放 PR；在授权与实际共享名额内继续独立工作。不能为清理队列丢弃独有成果、覆盖其他 Owner 或关闭未被实际替代的任务。
- 核对真实最新 HEAD、完整 Diff、普通评论、Reviews、Review Threads、Required Checks、审批、Owner 和 Ruleset。按最高实际风险判断必要验证；文档不机械运行无关游戏长跑。

### 1.2 Kody 审查
- Kody 是有实际文件改动的 Wiki PR 的必经审查，Balanced，不使用 Heavy。Wiki 独立统计，不占 Android/Web 共享主动审查额度；全项目并发、授权及周期预算仍按 Workspace。
- Ready 或新 HEAD 由原生配置触发；Draft 不提前收费。核实实际配置及回执；只有明确未触发或真实失败、授权、预算及并发均允许时才手动兜底。同 HEAD/配置不重复触发；禁止为形式上的 PASS 重复请求。
- Kody 官方 skipped 不计主动审查额度；按仓库、PR、HEAD、官方 Check Run 证据幂等释放预占或退额。GitHub Actions 自身 skipped、缺失回执或不明状态不足以证明 Kody skipped。真正完成的审查（含零发现）按适用计数规则记录，平台收费另核实。
- skipped、KODY NOT RUN、等待、超时、失败和 Provider 不可用均非 PASS。未取得真实审查结论时不冒充通过；不要因意见清零或 Summary 存在即认定 PASS。
- 审查意见先核实实际缺陷，集中修复并定向验证，必要时提供充分反证；真实阻断未解决不得合并。不能为了归零机械关闭线程或把 Kody finding 当作文笔模板。
- 无实际文件改动的 PR 按现行豁免；仅新增/修改 AGENTS.md（含子目录同名文件）且官方明确因规则文件而 skipped，并满足全部其他保护时，可按 Workspace 例外合并。混入任意其他路径不适用；官方跳过原因未知或 Required Check 未满足则阻断。
- Kody 通用审查标准归 Global Rules，仓库执行规则归 AGENTS.md 及专项文件。全局配置的修改必须有相应授权，不把项目特例复制到全局。

### 1.3 阻断与证据
- REVIEW_BLOCKED 必须带原因；quota 记录授权、Provider、预算/额度不足，concurrency-guard 记录并发隔离缺口。均记录 Owner、HEAD、CI、Review、已用/在途、证据与下一动作。解除前先核实实际条件恢复和最新 HEAD，不绕过。
- 内容问题用 EDITORIAL_BLOCKED，与 CI、Kody、保护、部署和环境问题独立。保护缺失或未验证记 PROTECTION_BLOCKED；未运行、失败、受阻、真实通过分别标识。
- 规则迁移逐条核实有效约束、归属位置和必要引用；保留历史 Git 记录。被替代的规则 PR 只有在替代内容实际合并且回读验证后才可按 SUPERSEDED 关闭，遗漏则记 RULE_INHERITANCE_BLOCKED。

## 2. 合并、部署与回读

- main 使用 GitHub 原生 Ruleset/受保护分支，要求 PR、Required Status Check Wiki PR CI（KB PR check 工作流，Job 名须唯一）及 Require conversation resolution before merging。合并前通过 GitHub 实际配置核验检查名称、启用状态、审批、最新 HEAD、全部应解决线程及其他保护。
- 作者自检、编辑复审、当前 HEAD 的 Kody 与 Required CI、合并、Pages 生产部署、线上验收是独立门禁，不能相互替代。不得强推、绕过分支保护或伪造回执。
- 成熟一批、审查一批、上线一批，不等全站结束。当前重构周期、交付期限、优先级以任务书为准；普通长期维护不为数量或频率制造无意义改动。
- 合并后回读 main 与合并 Commit；确认 GitHub Pages 对应部署真实完成、HTTPS、相关线上路由、移动/桌面阅读、导航搜索及受影响旧 URL。仅构建通过、仅合并或仅提交部署不等于上线验收。
- 线上失败定位根因并按授权恢复上个可用版本或定向修复，不删除唯一成果。记录真实 PR、候选 HEAD、合并 SHA、CI、部署与线上证据，更新逐页台账。
- 规则 PR 合并后通知实际执行 Owner 安全同步并回读，不以远端已合并冒充本机同步。

## 3. 执行与资源

- 按 Workspace 使用独立 worktree、明确文件 Owner、真实授权、资源锁与安全同步。保护未提交成果、存档、密钥、唯一证据及有效回滚点，不擅自清理其他 Owner 环境。
- 关键命令保留完整 stdout/stderr、真实退出码、HEAD、必要版本和日志位置；同一失败连续出现先查首次有效错误、进程/端口、资源、权限及版本，而非机械重试。
- 环境异常先以最小安全方案自主定位；有真实外部硬阻断才标 ENVIRONMENT_BLOCKED 并记录尝试、已排除原因、证据、Owner 和恢复动作。等待时继续独立任务，不虚报后台能力或 PASS。
- 跨仓 Android 发布、游戏验收、工具链、ABI、签名与五渠道交付依 Workspace 和责任仓规则；Wiki 不另立平行门禁，不擅自执行其他仓业务。
