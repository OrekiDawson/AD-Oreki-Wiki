# 导航版式与版权细则

> 承接原根 AGENTS.md 对应章节的有效规则。代码路径默认相对于仓库根目录；共性规则以 Workspace 最新权威版本为准。返回[规则入口](../../AGENTS.md)。

## 6. P1 导航覆盖与公开内容边界

### 6.1 导航是正式内容的发现入口

- Wiki 导航与内容可发现性为当前 P1。所有正式发布条目必须能从玩家专区、开发者专区的分类导航或自动生成的“全部条目”索引到达，导航覆盖率目标为 100%；不得把搜索、反向链接或读者恰好知道 URL 当作导航覆盖。
- Quartz 继续使用 `ordered-explorer`。正式分类和条目默认完整展开，不以折叠或隐藏条目解决导航冗长；通过语义排序、短侧栏标题、合理分类、较浅层级和独立滚动改善可发现性。目录标题负责进入分类索引，桌面端可使用独立折叠按钮，当前条目自动高亮并定位；移动端只保留整个导航面板的开启/关闭，不折叠单个分类。首次加载默认展开，读者主动调整的展开状态必须由 Explorer 保存，并在 SPA 页面切换后保留；切换页面只自动展开当前路径祖先，不得强制重置其他目录。玩家专区与开发者专区遵守同一原则。新增、迁移、拆分或合并页面必须同步更新分类、索引、站点地图和受影响链接。
- 导航空子菜单是硬错误：没有真实下级正式页面的 `index.md` 目录必须渲染为普通链接，不得显示展开箭头、空子菜单或空白虚拟分类；不得为了保留按钮人为新建占位页。CI 必须同时检查内容模型、失效/重复/遗漏链接、草稿/归档泄露、默认展开状态和构建后导航 DOM；桌面端与移动端均须通过实际浏览器验收。
- “全部条目”和“最近更新”必须由正式 `content/` 页面数据生成或校验，不维护容易失同步的手工副本。无合理豁免的孤立正式页面、失效导航链接、重复入口和旧兼容入口暴露均阻断 CI。
- 导航名称服务于读者理解，不机械暴露文件名、源码目录或内部命名空间；原版译文可在原版专区按基础机制、无限、永恒、现实、天神、挑战、成就、术语等主题组织，正式标题仍遵守 `原版:条目名` 命名规则。

### 6.2 内部历史归档不得进入公开内容树

- `content/developer/history/` 下的任务报告、失败记录、阶段性交接和旧构建证据属于内部归档，必须迁出 Quartz `content/`，统一放在仓库内部归档目录并保留 Git 历史；不得仅靠 CSS、`unlisted` 或导航隐藏伪装为已排除。
- 内部归档不得进入 Pages 构建产物、导航、搜索、全部条目索引、站点地图、RSS、关系图谱或反向链接。CI 必须检查归档路径、正式页面索引覆盖、配置行为和失效入口；覆盖率统计只包含正式发布条目，不包含草稿、归档、重定向和兼容入口。
- 历史材料中有长期价值的技术结论，应核实来源、去重后改写进现行开发者知识库；正式版本更新日志和具有百科价值的项目发展史可作为独立公开内容，但不得重新收录 Agent 流水账。
- Wiki 面向公众百科阅读，关闭 Quartz Graph（全局、局部及交互入口）；不得用 CSS 隐藏代替配置禁用。保留文章目录、有效相关条目导航、反向链接和搜索索引所需的数据结构，移除 Graph 后重新分配侧栏与正文空间，桌面端和移动端均不得出现关系图谱组件。

### 6.5 P1 MediaWiki 式百科界面方向

- **R130 收口时保留界面标准**：取消公共 Wikipedia 维护、研究或跨语言调查，不影响本节的 MediaWiki 式界面与版式要求。内容层允许独立作者风格；界面层继续遵循导航、目录、标题层级、正文宽度、表格、引用、内链、系统字体、深浅色模式、移动端适配及取消切页动画等既定标准；技术层继续使用 Quartz，不迁移至 MediaWiki 软件。最终验收按现行标准核对必要的桌面与移动阅读体验，不因此启动大规模 UI 重构。
- 将 MediaWiki Vector 2022 与英文原版 Antimatter Dimensions Wiki 的实际阅读体验作为 P1 参考方向，但继续使用 Quartz、GitHub Pages 和 Markdown，不为视觉相似引入新的后端或复杂框架。公共页眉、站名、搜索、左侧分类导航、右侧文章目录、正文宽度、字体层级、移动端折叠和深浅色模式应形成统一的百科阅读路径。
- 页面切换保留 Quartz 的 `enableSPA: true` 快速客户端导航，但目标页面必须直接呈现；不得显示 `.navigation-progress` 加载进度条、页面切换动画或 View Transition 动画。公共界面的运动效果不应制造人为等待，CI 必须检查该约束，桌面端和移动端线上验收均须确认。
- 通过可复用组件逐步提供 Infobox、Wikitable、消歧义/主条目提示、Navbox、Gallery、参考资料、分类导航和术语提示；组件应集中维护，页面只提供语义内容，不逐篇复制样式。不得伪造本站尚未实现的编辑、讨论或历史版本入口。
- 全站界面标题和正文使用操作系统原生无衬线字体，代码使用系统原生等宽字体；禁用 Quartz 自定义网页字体插件、Google Fonts 请求、字体预连接和普通第三方字体资源。KaTeX 等功能性数学字体可由数学插件单独保留。纯数字科学记数法（如 `1.80e308`）属于普通正文，不得无理由包成 KaTeX 或行内代码；含运算结构的真正数学公式才使用数学字体。CI 必须检查源配置、纯科学记数法语义和构建产物；Playwright 移动视口验收必须检查玩家、开发者、原版译文、表格、导航和数学/代码样本的实际 computed style，防止普通网页字体重新引入。
- 标签应服务于读者分类，必要的编辑元数据置于正文底部；公开页面不得展示内部历史归档、AI 草稿、Agent 工作日志或废弃入口。原版译文继续遵循英文原版的信息架构、图文组织、来源和许可边界。
- 第三方图片、字体、图标与样式资源必须登记版权清单。每批公共界面改造都须完成 Lead 复审、Kody、CI、Pages 部署及桌面/移动真实视觉验收；不得以构建成功代替可读性验收。

### 6.6 P0 内容结构治理：合并、拆分与新增

- Wiki 内部内容结构重构为当前 P0。正式原创玩家条目和开发者条目的边界由知识主题、读者任务、事实来源和阅读负担决定，不以现有 Markdown 文件数量、历史目录或旧 URL 数量为约束。每批必须实际完成至少一种有依据的合并、拆分、新建、替代归档或删除；建议清单、标题调整、导航修改、台账更新和普通润色不构成结构重构成果。
- Lead 可主动合并重复或碎片化页面、拆分混杂或过长页面、新建缺失的独立知识专题，并将无百科价值的内部材料迁出公开内容树。合并、拆分、迁移和删除必须保留必要的 aliases/重定向，更新所有站内链接、分类、索引、站点地图和旧 URL 映射；不得制造断链，也不得为完成数量指标强行改变文章边界。
- 原版 Wiki 忠实译文原则上保留英文原版条目边界及署名、许可和来源关系；玩家专区原创百科与开发者专区技术正文允许充分重组。历史报告、失败记录、交接材料和旧构建证据不得借结构调整重新公开，具有长期价值的知识须去重、核实后写入现行正文。
- 合并专项、拆分专项和新增专项可以由互不冲突的 Subagent 并行执行。每个专项必须直接修改实际正文，使用独立工作树和明确文件 Owner，不得只提交建议或共同修改台账。Lead 负责统一信息架构、解决冲突，并亲自完整阅读每个最终候选页面；未经 Lead 正文复审的文章标记 `EDITORIAL_BLOCKED`，不得合并或发布。
- 每批交付记录真实的源页面/目标页面合并关系、拆分原页面/新专题关系、新增条目、被替代或归档页面、重构前后知识架构、Diff、PR、Kody、CI、合并 Commit、Pages 部署和线上验收。完成率和正式页面总数必须从当前实际内容树重新计算，不得把兼容入口、重定向、归档和草稿重复计入。

### 6.3 P1 交付门禁

- 导航整改采用滚动发布：导航交互、双专区分类、原版主题入口、自动索引和 CI 门禁均可独立交付，但每批仍须经过 Lead 审阅、Kody、Required CI、正常合并、Pages 部署和真实桌面/移动端验收。
- 交付报告必须给出正式条目总数、已覆盖数量、覆盖率、孤立页面数量、归档排除证据、PR、CI、部署版本及实际页面截图；不能以改动行数、目录文件数或构建成功代替导航可用性验收。

### 6.4 第三方版权与原版译文视觉资料

- 全站第三方文章、图片、截图、图标、Logo、字体、图标库、Quartz 主题/插件和其他软件组件必须有可追溯来源、权利人、许可证、使用范围、修改说明和必要署名；不得把第三方素材笼统归入本站 CC BY-SA 4.0。统一版权入口为 `/copyright`，机器可读素材清单为 `docs/translation/original-image-manifest.json`。
- 原版译文应尽可能保留英文原文中承载知识的表格、图片、图标、画廊和动画。图片逐项审查来源与许可后才能下载到 `static/`；来源或许可无法确认时标记“待核实”，不得热链、发布或用 AI 生成的虚构截图替代真实素材。不得移除水印或版权标识。
- 原版图片恢复采用批量审计、分组恢复、Lead 复审和滚动发布。逐页记录原文图片数、已恢复数、缺失数、许可状态与整改进度；图片需有准确中文替代文本、必要图注，并通过桌面、移动、深浅色模式和构建产物检查。
- 新增、替换或删除第三方素材时必须同步更新版权页、机器可读清单和必要随文署名。CI 应阻断未登记素材、失效本地图片、缺少来源或待核实素材进入公开构建；不得以“文章本身采用 CC BY-SA 4.0”推导图片同样获授权。
