# Wiki 仓库目录与中文命名约定

> 权威规则：[知识库规则](https://wiki.oreki.net/wiki-rules) 与 [Agent 长期规则](https://github.com/OrekiDawson/AD-Oreki-Wiki/blob/main/AGENTS.md)。本页只说明目录职责和操作入口，验收命令以 [PR 检查工作流](https://github.com/OrekiDawson/AD-Oreki-Wiki/blob/main/.github/workflows/pr-check.yml)、[部署工作流](https://github.com/OrekiDawson/AD-Oreki-Wiki/blob/main/.github/workflows/deploy-wiki.yml) 与 `scripts/build-site.sh` 为准。

Wiki 面向中文玩家与开发者。**正文、导航、文章标题与维护说明以简体中文为准**，但 Quartz、Node、TypeScript、GitHub Pages 所依赖的固定文件名和现有页面 URL 不强制汉化。

## 根目录说明

| 位置 | 职责 |
| --- | --- |
| `README.md` | 唯一根目录项目入口，面向读者与贡献者 |
| `AGENTS.md`、`CLAUDE.md` | Agent 编辑与交付规则 |
| `LICENSE.txt`、`LICENSE-CONTENT.md` | 软件、原创中文内容许可与版权范围，保持约定入口 |
| `content/` | 经审核的公开百科条目与页面；`content/ai-drafts/` 仅作待审证据，不得进入公开页面、搜索索引或 RSS |
| `docs/` | 编辑手册、翻译规则、条目模板和构建维护说明 |
| `evidence/`、`reports/` | 经脱敏的测试与事实证据；不直接当作百科正文发布 |
| `scripts/` | 内容检查、构建与验证脚本 |
| `.github/`、`.ai/` | 工作流与工具配置，非普通玩家内容 |
| `quartz.*`、`package*.json`、`tsconfig.json`、`Dockerfile`、`*.d.ts` | Quartz/Node/TypeScript 工程入口，文件名由工具链约束 |

## 统一规则

1. 新文章的**展示标题、摘要、正文、导航和主要维护文档用自然简体中文**，避免直接把英文机器结构或 PR 日志复制成百科条目。
2. 文件名可按实际内容使用中文，但若改名会改变站点路由，必须验证旧 URL 仍可访问或有有效重定向；不能仅为“汉化”破坏外部链接、搜索或 Pages 构建。
3. 双专区的内容边界与导航原则以[知识库规则](https://wiki.oreki.net/wiki-rules#玩家与开发者各自说清楚)为准；目录调整不能绕过实际内容、导航、旧 URL、移动端、搜索、Quartz、CI 与 HTTPS 验收。具体交付检查由内部维护文档承接。
4. 技术组件、Quartz 配置、模块导入、Node/NPM 命令、GitHub workflow 名和许可证文本不强制翻译或重命名。
5. 历史证据归入 `evidence/` 或 `reports/`；对外说明归 `docs/`；不要在根目录追加临时进度、生成草稿或未审网页。
6. 所有路径调整按最小必要校验执行。凡本次改名的页面，必须在页面 frontmatter 配置 `aliases` 生成重定向，可同时把旧 slug 加入 `scripts/verify-build.mjs` 的 `LEGACY_URLS` 作为长期回归断言，再实际打开旧 URL 确认 200 或有效重定向。命令示例：仓库根运行 `node scripts/check-translation.mjs` 与 `bash scripts/bootstrap-quartz.sh .quartz-build`，再进入 `.quartz-build` 运行 `npm ci`、`npx quartz plugin install --from-config`、`node scripts/check-content.mjs`、`npx quartz build` 与 `node scripts/verify-build.mjs`；同时按改动范围补充其他适用检查。命令来源见文首 CI 工作流与 `scripts/build-site.sh`，未经实际运行不能记录 PASS。
