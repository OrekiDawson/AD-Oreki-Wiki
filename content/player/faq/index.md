第一次接触 Oreki Edition，最容易困惑的并不是数字有多大，而是「下一步该做什么」「为什么这个按钮不能用」「刚改的自动购买器设置怎么又变了」。下面把常见情况分开回答，先给能直接尝试的办法，再附需要进一步阅读的页面。

## Android 和 Web 选哪个？

**想在手机上用独立应用，就选 Android；想打开浏览器直接玩，就选 Web。**

Android 版从 [GitHub Releases](https://github.com/OrekiDawson/AD-Oreki-Edition-Android/releases) 下载对应 APK。Web 版可以打开 [oreki.net](https://oreki.net/)。

两个平台以玩家可见的玩法尽量一致为目标，但它们的发布版本与存档环境可能不同。遇到错误时，记得先确认自己用的是哪一端。

## Stable 和 Pre-release 有什么区别？

**Stable Release 是稳定发布，Pre-release 是提供给玩家提前测试的版本。** 预发布版可能已经可以安装和运行，但部分玩法测试、兼容性验证或已知问题仍未完成。

如果你最在意原有进度的安全，优先选择适合自己需求的稳定版本。准备体验 Pre-release 时，先查看对应版本的已知问题，并把原存档备份到游戏之外。

发行标签、下载文件和已知问题以[实际 Release 页面](https://github.com/OrekiDawson/AD-Oreki-Edition-Android/releases)为准，不能只看别人分享的 APK 名称。

## 刚开始应该先买什么？

从**反物质维度**和计数频率升级（Tickspeed）开始。第一维度生产反物质，更高维度逐级提供生产能力；当单纯购买越来越慢时，试着进行维度提升或反物质星系重置。

重置后数字变小通常是正常现象，因为你在用当前积累换未来更快的成长。完整入门见[开始游玩](/player/getting-started/)。

## 我第一次大坍缩了，为什么还没有永恒？

**第一次大坍缩解锁的是无限，不是永恒。** 你需要继续获取无限点数（IP），购买无限升级，逐步解锁无限维度，再向永恒所需的 IP 目标推进。

此时看到「打破无限」的相关内容，也不代表它已经能立即启用。先检查对应的升级条件。

如果刚完成第一次大坍缩，就出现了显然属于永恒或现实的可用功能，先不要依赖这个入口推进；这可能是特定版本的界面解锁异常。参见[阶段解锁与页面显示](/player/gameplay/stage-gates)。

## 自动购买器不工作怎么办？

先检查**资源够不够、对应功能是否已经解锁、当前挑战有没有限制、自动购买器是否启用**。自动购买器能帮你执行购买，但不能绕过真实资源和挑战要求。

Oreki Edition 的统一调度器默认每 **10 秒**重新检查一次受管策略，允许调整为 **1～60 秒**。这与原版自动购买器自身的购买间隔不是同一个设置。修改后先观察一两个节拍，而不是立刻判断失效。

详细区别见[智能自动购买器](/player/gameplay/automation)。

## 为什么我手动关闭的自动购买器又打开了？

**先分清普通受管项目与“自动永恒”例外。** 在当前 Android 实现中，调度器对明确受管的反物质维度、计数频率、维度提升、星系、大坍缩等项目，可能同时管理启用状态和其他配置。玩家临时修改这些受管字段后，下一次有效调度 tick 会按当前策略重新设置；要长期改变行为，应调整调度器本身的目标或设置。

**但手动关闭“自动永恒”应受到专门保护。** 原版现实结算有时会复位自动永恒开关，MOD 会在符合条件时修复这种复位；如果玩家明确手动关闭了自动永恒，当前的专用托管逻辑应保留这一选择。它不是普通受管字段的下一 tick 覆盖。如果手动关闭后无故又被打开，请记录当前版本、发生阶段和操作顺序并反馈。

是否受管、哪些字段由策略接管，仍以当前版本为准。具体规则见[智能自动购买器](/player/gameplay/automation)及 [Android R120 受管字段记录](https://github.com/OrekiDawson/AD-Oreki-Edition-Android/blob/3b2d8284f2aca7132168998ee32497b3c4c17b8e/reports/R120-01/scheduler-managed-authority.md)。

## 永恒挑战买不了，是不是资源不够？

不一定。**永恒挑战除了时间之理（TT），还可能要求你走对时间研究路线并满足额外条件。**

例如高级挑战有指定的前置研究；如果缺了这条研究链，单纯继续囤积 TT 或 IP 仍然无法购买。

先查看挑战说明，沿研究树检查上方节点；必要时在允许的时机重新分配研究。可以阅读[挑战与真实结算](/player/gameplay/challenges)和[现实与时间研究](/player/gameplay/reality-time-studies)。

## 现实之后时间研究都没了，是不是丢档了？

**不一定。** 现实属于更高层的重置，本来就会清除许多永恒及以下的进度，包括当前时间研究配置。你需要依靠现实机器、符文和复兴等奖励，使下一轮成长更快。

真正需要警惕的是高层永久进度无故消失、存档反复回退，或者重启后资源出现无法解释的变化。遇到这些问题时，先保留备份，参照[存档兼容与自动保存](/player/gameplay/saves)排查。

## 能把 Android 存档直接导入 Web，或从新版退回旧版吗？

**不要默认能够互通。** 两端及不同版本之间的保存与读取能力可能有差异，即使第一次导入时页面看起来正常，也不表示再次保存和重启都能成功。

尝试导入前，先导出旧存档并保留一份不被覆盖的副本。导入后需要至少检查主要进度、游戏能否继续推进、再次保存以及重新打开后的结果。**不要用唯一的一份存档做兼容性试验。**

## Oreki Edition 一定能在三小时内通关吗？

**三小时（180 分钟）是项目希望达到的真实新档体验目标，不是对每个版本、每位玩家或每种操作方式的通关保证。**

不同版本的错误、手动选择和自动化状态都可能影响时间。某个历史测试通过，也不能证明你手里的 APK 已经通过同样测试。当前测试和发布状况可以在[项目状态](/developer/current/project-status)查看。

## 出了问题，怎样报告更有帮助？

先保留原存档，不要为了复现不停覆盖正常备份。反馈时说明：

- **平台与版本**：Android 的 Release 标签或 Web 的版本信息。
- **发生阶段**：例如第一次大坍缩后、第三次永恒挑战、第一次现实后。
- **操作过程**：先做了什么，哪个按钮不起作用，是否能够再次复现。
- **预期与实际结果**：本来应该发生什么，屏幕上实际出现了什么；必要时附截图。

Android 的问题可以在[Android 仓库 Issues](https://github.com/OrekiDawson/AD-Oreki-Edition-Android/issues)反馈，Web 的问题则到[Web 仓库 Issues](https://github.com/OrekiDawson/AD-Oreki-Edition-Web/issues)。不要把账号令牌、私人文件路径或含有敏感信息的存档直接公开。
