天神系统看起来像一组页面，实际上是一张由成就、现实升级、资源、位图和重置状态共同决定的状态图。开发者真正需要维护的不是“页面能不能点开”，而是每条边的前置条件是否在正确的时间、以正确的编码写入存档。本页讨论 Web 上游实现与 Android 适配层如何表达这些条件，以及如何避免跨端移植最隐蔽的错误：数值看起来对，状态却永远走不到下一步。

## 把解锁看成状态转移

以虚构升级 IU15 为例，Web 的 `imaginary-upgrades.js` 将它描述为一个真实的升级对象：成本是 $10^9$ 虚幻机器，购买条件同时要求当前现实没有买过第一无限维度，并且反物质指数达到项目常量 `OREKI_IU15_AM_EXP`。`hasFailed()` 记录“本现实已经买过 ID1”的不可逆失败条件，`checkRequirement()` 才决定当前是否可买。

这意味着 IU15 不是一个布尔开关，而是一条带历史的转移：

```text
未买 ID1 + 指数不足  →  等待产量
未买 ID1 + 指数达标  →  允许购买 IU15
已买 ID1              →  本现实内失败，等待下一次现实重置
```

把这种条件简化成“指数够不够”会制造死锁：自动化会一直攒资源，却永远无法消除已经写入的 `maxID1`。

IU25 的结构类似但更深：必须处于莱特拉现实、禁用足够多的维度、满足符文槽限制并完成现实。进入佩勒后又会改变 `break`、自动购买器和终局状态的可用性。开发者因此应先画状态转移，再写策略叶子；否则策略只是在猜页面文案。

## 结算产物

阶段和天神判据经常跨越一次重置。Android 的 `OrekiGuiStage` 不把 `Player.eternities` 单独当作永恒真值，而是组合永恒点数、`bigEternities`、永恒升级位图以及更高层现实结算产物；现实阶段则看 `realities` 或 `bigRealities`。这是因为高层重置可能清理低层计数，兼容存档也可能保留一个非零但没有真实结算意义的字段。

Web 端则由上游天神模块和升级状态对象计算可用性。两端的实现不必共享方法名，但必须共享“真实结算才能推进”的语义。诊断时应同时读取：

- 进入条件所依赖的资源或成就；
- 记录结算历史的计数与大数副本；
- 升级位图及其本端编号；
- 当前重置上下文，例如是否处于莱特拉或毁灭态。

只看导航栏或一个 `unlocked` 布尔值，无法区分判据错误和 UI 缓存错误。

## 位图是跨端移植的地雷区

Web 上游使用升级对象的 `id` 组织虚构升级；Android 的移植层则把相关状态压进本端位图。IU15/IU25 在两端的位号并不相同，Android 策略叶子必须按 Android 本端的位号读取，不能把 Web 的 15、25 直接平移过去。

排查位图问题时应做三步：

1. 在本端源码或反编译资料中找到“写入位”和“读取位”两处，而不是只看字段名。
2. 用 `1L shl bit` 或等价掩码计算一个已知状态，确认读取器没有把 `BitSet` 对象误当成整数。
3. 用一个已知存档验证位值、页面状态和策略叶子三者一致。

位号错一位的症状很像“天神系统坏了”：页面可能打开，但 `laitelaUnlocked` 或 `pelleUnlocked` 永远为假，自动化于是停在旧阶段。它本质上不是数值平衡问题，而是 ABI/编码契约被破坏。

## 数值调整与原版语义要分开

本 MOD 会改变部分门槛和成本，例如 Web 当前源码把 IU15 的反物质指数门槛集中成常量，并把 IU25 成本接到 MOD 常量；这类调整属于平衡层。解锁条件的组合、购买时的真实扣除、失败条件与重置清理仍属于机制层。

修改数值时，优先保持机制层不变：让购买继续走 `ImaginaryUpgrade.purchase()`，让资源继续通过 `Currency` 扣除，让锁定状态继续由状态对象计算。若为了“方便自动化”直接写入位图或跳过购买，测试也许会更快，却失去了对存档兼容和真实进度的意义。

## 从判据到策略的调用链

一条可追踪的 Android 链路是：

```text
player 字段 / 位图
    ↓
GameApi 读取器
    ↓
OrekiStrategyLeaves 的 celestial.* 判据
    ↓
OrekiStageAuto 选择阶段动作
    ↓
原版购买、重置或结算入口
```

Web 端的对应链路是：

```text
player.celestials / Currency / UpgradeState
    ↓
天神与虚构升级状态对象
    ↓
OrekiSmartStrategy 选择动词
    ↓
OrekiSmartExecutor 注册模块
    ↓
真实游戏动作与事件循环
```

任何一层读取失败，都应安全地返回“未知/不可用”，而不是把未知当成已解锁。尤其是存档缺字段、版本迁移尚未完成或天神对象尚未初始化时，失败开放会比失败关闭更难发现。

## 排障路线

若天神页面可见但策略不前进，先检查本端位图与读取器；若策略判定正确但购买失败，检查当前现实上下文、资源扣费和 `hasFailed`；若购买成功但下一阶段仍不可见，检查重置后缓存刷新与导航守卫。若 Android 与 Web 分叉，先用同一已知存档比较编码，再比较动作调用链，最后才比较数值常量。
